# Local Assistant Engine --- 06.1 Tech Stack

6 Nov 2026 • @Ved Narvekar

## Summary

One main language, Rust, runs both the app and the server. Models are
open source. Python is used only offline, if a model needs fine-tuning.

| Layer | Main stack |
| --- | --- |
| On the laptop | Rust core • Tauri + React UI • ONNX Runtime + llama.cpp for models • SQLite with SQLCipher |
| Models | Open-source models first • fine-tune only where none work • Python + PEFT if needed |
| Update server | Rust (Axum) • PostgreSQL • object storage + CDN |
| Build and test | GitHub Actions with Windows runners • cargo test • nightly test-set runs on an 8GB laptop |

## Key choices explained

**Rust, not Go, for the app.** The app must idle under 300MB and never
pause. Go uses a garbage collector, which adds memory and small pauses.
Rust has neither. Rust also has strong Windows bindings for UI
Automation and system APIs, and good bindings for ONNX Runtime and
llama.cpp. Go would be fine for a server, but not for this app.

**Rust for the server too.** The server is small. Using Rust there lets it
share code with the app, like the skill format and package signing. One
language means a smaller team can cover everything. Go remains a fine
alternative if the team prefers it.

**Tauri, not Electron, for the UI.** Electron ships a full browser and often
uses hundreds of MB. Tauri uses the web view already built into Windows
(WebView2), so the UI stays light. Its backend is Rust, which matches
the core.

**SQLite on the laptop, PostgreSQL on the server.** PostgreSQL is a server
database. Running it on every laptop would waste memory and need setup.
SQLite is a single file with no server, ideal for local data. PostgreSQL
fits the update server, which stores accounts, licenses and release info
for many users.

## On the laptop

| Area | Choice | Why |
| --- | --- | --- |
| Core language | Rust | Low memory, no GC pauses, safe, cross-platform |
| Async runtime | Tokio | Standard for async Rust; runs connectors in parallel |
| UI shell | Tauri 2 | Light; uses Windows' built-in WebView2 |
| UI code | React + TypeScript | Large talent pool; fast to build the command bar |
| Encoder inference (Tier 0) | ONNX Runtime, via the ort Rust crate | Fast on CPU; int8 models; optional GPU later |
| Base model inference (Tier 1) | llama.cpp, via Rust bindings | Runs 4-bit GGUF models on CPU; supports LoRA adapters and grammars |
| Tokenizers | Hugging Face tokenizers crate | Same tokenizer in training and on device |
| Local database | SQLite + SQLCipher, via rusqlite | One encrypted file, no server |
| Windows APIs | windows crate (windows-rs) | Official Microsoft bindings: UI Automation, media controls, Bluetooth, Wi-Fi, notifications, Credential Manager |
| HTTP and sign-in | reqwest + oauth2 crates | Calls Google APIs and Microsoft Graph |
| Data formats | serde (JSON and YAML) | Skill files, IPC messages, API data |
| IPC | Windows named pipes, via Tokio | Fast local messages between processes |
| Logging | tracing crate | Structured local logs |
| Astronomy and math | Own Rust code, standard formulas | Moon phases and sunrise work offline |
| Auto-update | Tauri updater | Signed updates from the update server |

Crate names are current picks. Each gets a quick check for upkeep and
license before Phase 1.

## Models: open source first

We use ready-made open-source models wherever they are good enough. We
fine-tune only where nothing off the shelf works. We never train a model
from scratch.

| Job | Off-the-shelf plan | Fine-tune only if |
| --- | --- | --- |
| Router and skill matching | Open-source embedding model (bge-small or MiniLM class). Matches requests to the example phrases in each skill. No training. | SP1 stays under 95% accuracy |
| Extraction (names, files, times) | Open-source zero-shot extractor (GLiNER class), plus simple rules for dates and times | SP2 stays under 95% accuracy |
| Email urgency | Rules (key senders, deadline words) plus the embedding model | Beta users find it unreliable |
| Planner, summaries, reply drafts | Open-source 1--3B instruct model (Qwen, Gemma, Phi or Llama small class), with good prompts and grammar checks | SP3 fails on chained tasks |

### If fine-tuning is needed

- It stays small: a LoRA adapter or a classifier head, never a full
    model.
- No own hardware needed: rent one cloud GPU by the hour, or use
    low-cost notebook GPUs for the smallest models.

- Training data: the test-set wording, plus examples generated by a
    large model and reviewed by people.
- Tools: Python, PyTorch, Hugging Face Transformers and PEFT. Export
    to ONNX (Tier 0) or GGUF (Tier 1).

Licenses: prefer Apache 2.0 or MIT models. Some families, like Llama and
Gemma, have their own terms. Check them for commercial use before
SP1--SP4.

## Models used by each task

All 49 tasks share just three models. Most tasks never use the 1--3B
model at all. The actual work, like sending on WhatsApp, is done by
code, not by a model.

- Embedding model: picks the task and fuzzy-matches loose names, like
    "budget thing."
- Extractor (GLiNER class): pulls out contacts, files, apps, songs,
    times and places.

- 1--3B instruct model: writes summaries and drafts, and plans chained
    requests.

| Area | Pick the task | Pull out details | Write or plan |
| --- | --- | --- | --- |
| Apps and media (A1--A6) | Embedding model | Extractor: app, song, artist, creator | Not needed |
| Messaging (M1--M4) | Embedding model | Extractor: contact, file, message text | Not needed; the message words are used |
| Email (E1--E7) | Embedding model | Extractor: person, topic, date | 1--3B model for summaries; urgency (E1) uses rules |
| Quick info (Q1--Q5) | Embedding model | Extractor + date and time rules | 1--3B model only to produce summaries / plans \[right edge clipped\] |
| Files (F1--F6) | Embedding model | Extractor: file name, folder, person | Not needed |
| Calendar (C1--C8) | Embedding model | Extractor + date and time rules | 1--3B model only for planning \[partially clipped\] |
| Reminders (R1--R2) | Embedding model | Extractor + time rules | Not needed |
| Workflows (W1--W6) | Embedding model | Extractor | Saved templates first for chains; 1--3B summaries \[partially clipped\] |
| System (S1--S5) | Embedding model | Extractor: on or off, amount, duration | Not needed |

Example, "Send this file to Ved on WhatsApp": the embedding model picks
whatsapp.send_file. The extractor finds "this file" and "Ved." Code
finds the selected file and the right contact, shows the confirm, drives
WhatsApp and checks the file was sent. The 1--3B model never loads.

## Update server

| Area | Choice | Why |
| --- | --- | --- |
| Language and framework | Rust + Axum | Shares code with the app; fast and light |
| Database | PostgreSQL | Accounts, licenses, release and rollout info |
| DB access | sqlx crate | Checks SQL queries at compile time |
| File storage | S3-compatible object storage | Holds installers, models, adapters and skills |
| Delivery | A CDN in front of storage | Fast downloads worldwide |
| Package signing | Ed25519 signatures | Small, fast; the app refuses unsigned files |
| Payments | Stripe, or a local provider like Razorpay | Free and paid plans |
| Crash reports | Sentry, opt-in, personal data stripped | Finds bugs without collecting user content |
| Hosting | Docker containers on a managed cloud service | Simple to run with a small team |

The server never receives requests, files, messages or learned habits.

## Build, test and release

| Area | Choice | Why |
| --- | --- | --- |
| Code hosting | GitHub, one repo for app + server + skills | One place for all code and reviews |
| CI | GitHub Actions with Windows runners | Builds and tests every change on Windows |
| Unit tests | cargo test (Rust), Vitest (UI) | Standard for each language |
| Connector tests | Rust tests driving real apps through UI Automation | Catches breaks when apps update |
| Test-set runner | Custom Rust tool running the 100 tests from 04 | Same tool for release gates and competitor benchmarks |
| Nightly runs | A real 8GB Windows laptop in the office | Measures true memory and speed |
| Installer | MSI or NSIS installer, built by Tauri's bundler | Clean install, update and uninstall on Windows |
| Code signing | Windows code-signing certificate | Avoids SmartScreen warnings |
| Frontend packages | pnpm | Fast, reliable installs |
